To execute PySpark .py files stored in a Google Cloud Storage (GCS) bucket, you will use the DataprocSubmitJobOperator. 
This operator instructs Google Cloud Dataproc to pull your script directly from GCS and run it on a managed Spark cluster.

Prerequisites
Before deploying this DAG, ensure you have configured your environment:
Airflow Connection: A Google Cloud connection configured in Airflow named google_cloud_default.
Dataproc Cluster: An active Dataproc cluster running in your GCP project.
File Paths: Your PySpark code must be uploaded to a bucket path (e.g., gs://your-bucket-name/scripts/my_spark_job.py).

# Encloses parallel ingestion tasks within brackets to fork execution simultaneously
start_cluster >> [hospitalALanding, hospitalBLanding, claimsLanding] >> stop_cluster


Critical Cloud Cost Protection (trigger_rule="all_done"): 
In your original script, if submit_hospital_b failed, the pipeline would halt immediately. Because the flow stopped, stop_cluster would never execute, leaving your Dataproc cluster running indefinitely and racking up massive Google Cloud bills. Adding "all_done" ensures that the cluster shuts down cleanly regardless of job status.

Optimized Execution Window: Instead of waiting for HospitalA to finish before HospitalB starts, Dataproc schedules them all concurrently. If each script takes 10 minutes, your pipeline now finishes in roughly 10 minutes total instead of 30 minutes.

Smart Resource Utilization: Dataproc handles distributed scaling naturally. Running jobs in parallel fully utilizes your cluster's CPU and memory capacity instead of letting slots sit idle.
