A Parent DAG is an Apache Airflow Directed Acyclic Graph (DAG) that coordinates, schedules, or triggers other independent DAGs 
(known as Child DAGs or SubDAGs).In modern Airflow architecture, instead of writing one massive, unmanageable file containing hundreds 
of tasks, you break your workflows into smaller components and use a Parent DAG to manage the execution order.
The standard industry practice is to use the TriggerDagRunOperator. This operator allows the Parent DAG to trigger 
isolated, standalone Child DAGs.

        task_id="trigger_pyspark_ingestion",
        trigger_dag_id="gcs_pyspark_dataproc_parallel_pipeline", 
        wait_for_completion=True,  # Blocks downstream steps until ingestion finishes completely
        poke_interval=15,          # Checks status of the child pipeline every 15 seconds
        reset_dag_run=True,        # Automatically clears and reruns child DAG if it already ran today
        allowed_states=["success"] # Requires a strict "success" state from child to move forward
    )

    # 4. Task Transformation: Trigger the BigQuery Medallion SQL Pipeline
    # Fixed: Updated trigger_dag_id to match our optimized sequential BQ child DAG
    trigger_bigquery_transform = TriggerDagRunOperator(
        task_id="trigger_bigquery_transform",
        trigger_dag_id="bigquery_medallion_pipeline",
        wait_for_completion=True,  # Ensures master DAG waits for final gold layer completion
        poke_interval=15,          # Checks status of the child pipeline every 15 seconds
        reset_dag_run=True,        # Automatically clears and reruns child DAG if it already ran today
        allowed_states=["success"] # Requires a strict "success" state from child to finish pipeline
    )

    # 5. Core Topology Sequence
    # Ingestion MUST complete successfully before BigQuery transformations are initiated
    trigger_pyspark_ingestion >> trigger_bigquery_transform

reset_dag_run=True: In production, pipelines fail and need to be re-run. If you run this parent DAG a second time manually, this parameter allows Airflow to clear out the child DAG's previous status and execute it fresh. Without this, the task would freeze or fail immediately.
allowed_states=["success"]: Added this parameter to ensure strict dependency gating. If your PySpark ingestion cluster throws an error, this flag stops the pipeline from moving forward, preventing your BigQuery tasks from running on missing or corrupted data.

#Key Benefits of This PatternComponent 
Isolation: If your pyspark transformation logic breaks, you can clear and re-run just the gcs_pyspark_dataproc_pipeline DAG without re-running the 
entire upstream Bronze pipeline.
UI Cleanliness: Your main Airflow dashboard stays clean. You see one master pipeline pipeline instead of a massive, messy web of 50 consecutive tasks.
Dynamic Parameters: You can pass data from the Parent down to the Child dynamically using the conf parameter inside the operator
