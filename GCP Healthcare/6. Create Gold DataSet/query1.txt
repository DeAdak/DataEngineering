INSERT INTO avd-databricks-demo.gold_dateset.provider_charge_summary 
SELECT CONCAT(p.FirstName,' ',p.LastName) as Provider_Name, 
		d.Name as Department, 
		SUM(t.Amount) as Charge_Amount
FROM `avd-databricks-demo.silver_dateset.transactions` t
LEFT JOIN `avd-databricks-demo.silver_dateset.providers` p
ON t.ProviderID = SPLIT(p.ProviderID,'-')[SAFE_OFFSET(1)]
LEFT JOIN `avd-databricks-demo.silver_dateset.departments` d
ON d.SRC_DeptID = p.DeptID
WHERE t.is_quarantined = FALSE AND d.Name IS NULL
GROUP BY Provider_Name, Department;

CREATE TABLE IF NOT EXISTS avd-databricks-demo.gold_dateset.provider_charge_summary(
							Provider_Name	STRING,
							Department		STRING,
							Charge_Amount	NUMERIC
							);

Use NUMERIC (or BIGNUMERIC) for exact math, and FLOAT64 for approximate math. The critical difference is that NUMERIC prevents rounding errors by storing numbers as exact decimals, 
while FLOAT64 is an approximate type that can introduce tiny trailing decimals during calculations due to binary floating-point representation.

Choose NUMERIC if you are handling:
💰 Financial data, currency calculations, or monetary billing.
📦 Inventory counts, fixed metric ratios, or exact quantities.
📊 Data where 0.1 + 0.2 must equal exactly 0.3.

Choose FLOAT64 if you are handling:
🔬 Scientific measurements, sensor telemetry, or GPS coordinates.
📈 Machine learning features, statistics, or data involving huge scales.
🚀 Queries where computation speed and lower storage costs are more important than exact precision.
