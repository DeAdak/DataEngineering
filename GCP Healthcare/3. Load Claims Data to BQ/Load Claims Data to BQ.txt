This code is setting up a Data Ingestion Pipeline that extracts raw medical insurance claims data from Google Cloud Storage (GCS), cleans 
it up using PySpark, and loads it into a Google BigQuery data warehouse table.
1. Prepares the Destination (BigQuery Table)
2. Reads Raw CSV Files
3. Identifies the Data Source Dynamically
4. Cleans and Deduplicates
5. Standardizes and Formats Columns
6. Appends Data to BigQuery

from pyspark.sql import SparkSession
from pyspark.sql.functions import input_file_name, when, col, to_date

# Initialize Spark Session
spark = SparkSession.builder.appName('Claims').getOrCreate()

# Google Cloud Storage (GCS) Configuration
GCS_BUCKET = 'healthcare-bucket-22032025'
CLAIMS_FILE_PATH = f'gs://{GCS_BUCKET}/landing/claims/*.csv'
TEMP_GCS_BUCKET = f'gs://{GCS_BUCKET}/temp/'

#BigQuery Configuration
BQ_PROJECT = 'avd-databricks-demo'
BQ_CLAIMS_TABLE = f'{BQ_PROJECT}.bronze_dataset.claims' # Note: Spark BQ connector prefers NO backticks in the string parameter

# claims_df = (spark.read.option('inferSchema','true').csv(CLAIMS_FILE_PATH ,header = True))

# By default, spark.read.csv reads all columns as STRING data types unless you explicitly define a schema or pass .option("inferSchema", "true").
# inferSchema=True on a raw CSV. Spark will guess numeric fields as integers or doubles and dates as strings. This creates a type mismatch when 
# writing to your BigQuery table, which strictly expects DATE and NUMERIC types, resulting in a BigQuery write failure. The dates must be explicitly 
# cast to date types using to_date().

# 1. Read raw CSV data 
claims_df = spark.read.option('header', 'true').csv(CLAIMS_FILE_PATH)
 
claims_df = claims_df.withColumn(
    'datasource',
    when(input_file_name().contains('hospital1'), 'HospitalA')
    .when(input_file_name().contains('hospital2'), 'HospitalB')
    .otherwise('None')
)
#.when(condition, value).when(condition, value).otherwise(value)


# 2. Deduplicate records
claims_df = claims_df.dropDuplicates()

# 3. Explicitly cast columns to guarantee they match the BigQuery Table definition
# This prevents write crashes caused by inferSchema guessing wrong types

transformed_df = claims_df.select(
    col("ClaimID").cast("string"),
    col("TransactionID").cast("string"),
    col("PatientID").cast("string"),
    col("EncounterID").cast("string"),
    col("ProviderID").cast("string"),
    col("DeptID").cast("string"),
    to_date(col("ServiceDate"), "yyyy-MM-dd").alias("ServiceDate"),  # Ensures strict BQ DATE format
    to_date(col("ClaimDate"), "yyyy-MM-dd").alias("ClaimDate"),      # Ensures strict BQ DATE format
    col("PayorID").cast("string"),
    col("ClaimAmount").cast("decimal(38,9)").alias("ClaimAmount"),    # Matches BQ NUMERIC precision
    col("PaidAmount").cast("decimal(38,9)").alias("PaidAmount"),      # Matches BQ NUMERIC precision
    col("ClaimStatus").cast("string"),
    col("PayorType").cast("string"),
    col("Deductible").cast("decimal(38,9)").alias("Deductible"),
    col("Coinsurance").cast("decimal(38,9)").alias("Coinsurance"),
    col("Copay").cast("decimal(38,9)").alias("Copay"),
    to_date(col("InsertDate"), "yyyy-MM-dd").alias("InsertDate"),
    to_date(col("ModifiedDate"), "yyyy-MM-dd").alias("ModifiedDate"),
    col("datasource").cast("string")
)


# 4. Save the data securely to BigQuery
# inferSchema is not a valid option for writing data.inferSchema is an option used exclusively when reading raw files (like CSVs or JSON) to help 
Spark guess the data types. When you are writing a DataFrame to BigQuery, Spark already knows what types its columns are.
(transformed_df.write.format('bigquery')
				.option('table',BQ_CLAIMS_TABLE)
				.option('temporaryGcsBucket',TEMP_GCS_BUCKET)
				.mode('append')
				.save())

print("Claims data loaded successfully into BigQuery!


#The purpose of .option('temporaryGcsBucket', TEMP_GCS_BUCKET) is to provide a temporary staging area in Google Cloud Storage (GCS) where 
#PySpark can drop data files before moving them into BigQuery .Without this option, Spark cannot write data to BigQuery at all.
#Here is why this staging bucket is required and how it works behind the scenes:
#1. BigQuery Does Not Accept Direct Row Streaming (At Scale)Spark handles massive, distributed data sets across multiple computers 
#(worker nodes). BigQuery, however, is designed to ingest large amounts of data quickly by loading files in bulk.
#2. How the Staging Process Works
#When you execute the .save() command, the Spark BigQuery connector completes the transfer in two steps:
#The Export Step: Spark exports your processed DataFrame out of memory and saves it as highly compressed, temporary files (usually Avro or 
#Parquet format) inside the TEMP_GCS_BUCKET you provided.
#The Load Step: BigQuery triggers a high-speed, native bulk-import job to pull those temporary files out of the GCS bucket directly into 
#your target table
#3. Automatic Cleanup
#Once BigQuery successfully imports the data, the connector automatically deletes the temporary files from your TEMP_GCS_BUCKET so you do 
#not get charged for storing duplicate data.
